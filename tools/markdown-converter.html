Converting web and Notion text to Markdown

Markdown is a compact, readable way to express document structure using plain text. A heading is marked with hash characters, emphasis uses asterisks, and a link keeps its destination beside its label. The source remains understandable even before it is rendered. This converter keeps only a small set of those structures from pasted content and discards the rest, so it helps to know exactly what survives.

How pasted HTML becomes Markdown

When you paste into the Input panel, the browser inserts the clipboard contents into the editable area. Each time that area changes, the converter reads its HTML and rewrites a fixed list of elements:

Pasted HTMLMarkdown output
h1, h2, h3#, ## or ### heading, then a blank line
h4 to h6Plain text with no line break after it, so it runs into the next block
strong, b**bold**
em, i*italic*
a with an href[label](address), with the address copied exactly as written
li in any listA - bullet line; numbered lists lose their numbers, and a nested item is joined onto its parent's line
pIts text, then a blank line
brA single line break
Everything else, including table, blockquote, pre, code, img, del, checkboxes and divThe tag is removed and its text kept, with no line break added; images and checkboxes disappear entirely and table cells run together

GitHub Flavored Markdown is a strict superset of CommonMark, with extensions such as tables, task list items and strikethrough (text between one or two tildes). This converter generates none of those extensions; its output uses only syntax that CommonMark itself defines, which GFM also accepts. GitHub applies its own post-processing and sanitization after rendering GFM, so preview a complex document where it will be published.

Fonts, colors, sizes and layout are not carried over, because every attribute except a link's address, including inline styles, is discarded along with its tag. Only the element type decides the result: a large bold line that is not an h1 to h3 element becomes bold text, not a heading.

A reliable conversion workflow

  1. Select only the document content you need. On a web page, avoid copying site navigation, cookie messages, share buttons, or related-post modules. A focused selection creates a cleaner source.
  2. Paste into the Input panel with the normal browser paste command. The panel shows the pasted formatting, including parts the Markdown output will not keep.
  3. Review the Markdown output. Check heading levels, link addresses and list items, look for anything the table above says is dropped, and confirm that each pair of ** or * markers wraps the words you expect.
  4. Fix by hand, then copy or download. The output box is editable, but the converter overwrites it the next time the input changes, so make manual fixes last. Copy Markdown puts the text on the clipboard; Download .md saves it as document.md.

For long pages, convert one meaningful section at a time, which makes it easier to see where an unsupported block was flattened. When you combine sections, one blank line between blocks is enough: CommonMark ignores additional blank lines between block-level elements, except where they decide whether a list is tight or loose.

Markdown syntax quick reference

Use these patterns to restore what the converter drops. The last column shows whether this tool writes the pattern for you.

ElementMarkdownWritten by this tool
Heading## Section headingLevels 1 to 3 only; type four to six # characters for deeper levels
Bold and italic**important** and *emphasis*Yes
Link[descriptive label](https://example.com)Yes
Image![useful alt text](image.jpg)No, images are removed
Quote> A concise quotationNo
Task item (GFM)- [x] Completed taskNo
Inline code`npm run build`No
Table (GFM)| Name | Status | then | --- | --- |No

The text in square brackets after ! becomes the image's alt attribute when rendered to HTML, so write a description there rather than leaving it empty. A GFM table has a single header row followed by a delimiter row with the same number of cells, and block-level elements such as lists cannot go inside a cell. If the source table has merged cells or several header rows, simplify it before rebuilding it.

Working with Notion pages

To move more than a few pages, use Notion's own export instead. Notion can export a page, a database or a whole workspace (Settings, then General under Workspace, then Export all workspace content) in its Markdown & CSV format: full-page databases become CSV files with a Markdown file for each subpage, and callout blocks are exported as HTML because Markdown has no equivalent. Keep that export as an archive, and use this converter for individual sections you want to tidy by hand.

Heading levels deserve special attention. Nest headings by rank without skipping levels, because browsers and assistive technologies can use headings to provide in-page navigation. Since only levels 1 to 3 convert, change deeper headings to level 3 before copying, or add the extra # characters afterwards.

Web pages, images and links

Select the article body instead of the entire page. Images are removed during conversion, so add each one back with the image syntax above and a written description. Also check relative links: the converter copies each address as it appears in the pasted HTML, and a domain-relative address such as /guide/setup takes its protocol and domain from whichever page displays it, so it may need the original domain added once the Markdown is published elsewhere.

Code blocks, line breaks and escaping

Code loses its Markdown formatting. The converter removes code and pre tags, so inline code arrives without backticks and a code block arrives as ordinary lines without a fence. It also reduces any run of blank lines to a single blank line, inside code as well. Wrap each block in a fence of at least three backticks. The first word after the opening fence, such as ```javascript, is typically used as the language name, although CommonMark does not require any particular treatment of it.

A br tag becomes a single line break, which CommonMark treats as a soft break that may be rendered as a space. Where the break matters, end the line with two spaces or a backslash to make it a hard line break.

The converter does not escape characters that Markdown treats as syntax. When literal asterisks, underscores, brackets, or hash characters are misread as formatting, put a backslash before them; CommonMark allows a backslash before any ASCII punctuation character.

Review the result before publishing: check the beginning and end first, then scan headings, links, lists and every place where a table, image, quote or code block used to be.

Frequently asked questions

Which Markdown format does the output use?

CommonMark syntax only: # headings for levels 1 to 3, ** and * emphasis, inline links and - bullets. Because GitHub Flavored Markdown is a strict superset of CommonMark, the output is also valid GFM, but GFM tables, task lists and strikethrough are not generated even when the pasted HTML contains them.

Why did a table, image or special block become plain text?

Any element that is not in the mapping table loses its tag and keeps only its text. Table cells run together, quotes lose their > marker, and images and checkboxes disappear. Rebuild those parts with the syntax in the quick reference.

Will the downloaded file preserve non-English characters?

Yes. The file is built with the browser's Blob constructor, which encodes text as UTF-8, so Korean, Japanese, accented letters and other Unicode characters are kept.
