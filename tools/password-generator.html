A few good questions

Does this generator save or send my passwords?

No. Password processing happens in browser memory. This file includes no analytics, cookies or browser storage. Copying sends the text to your system clipboard, where clipboard history or other apps may retain it. Google Fonts receives ordinary connection metadata when fonts load, but never password values.

Does “Unbreakable” mean impossible to compromise?

No. It is the top visual label for generated outputs with at least 100 modeled bits. It is not a guarantee. Phishing, malware and compromised recovery channels can bypass exhaustive guessing.

Does this work offline?

Yes. Save this HTML file and open it in a modern browser. Generation and analysis do not need a server. Fonts fall back to system fonts offline. Clipboard support depends on browser permissions; manual selection remains available.

Why are generated and manually entered estimates different?

Generated output has a known random selection process. Manually entered text does not. The checker penalizes some obvious patterns, but cannot detect every weak choice or determine whether a credential has been leaked.

Practical password workflow

Start by choosing the output type for the account. A generated password is a strong default for a password manager because every character can be random. A passphrase is useful when you must type the value by hand. A PIN is appropriate only where the system imposes a numeric format and rate-limits attempts. Generate a fresh value for every account; changing a few characters in an old password preserves patterns an attacker can exploit.

The strength panel models the search space of the generation method. Sixteen uniformly selected characters from a 72-character alphabet represent roughly 98 bits because 16 × log2(72) is about 98. A four-word phrase drawn independently from a 1,000-word list represents about 40 bits because each word contributes about 10 bits. The exact figures change with list size and selection rules. Human-selected phrases are not equivalent to randomly selected phrases, even when they have the same visible length.

Use the result safely

Copy the generated value directly into the destination and save it in a reputable password manager. Confirm that the destination accepted every character and did not silently truncate the value. Turn on multi-factor authentication when available. For an important account, store recovery codes in a separate protected location and test the recovery path before an emergency.

A common mistake is emailing a password to yourself or leaving it in a chat. Another is using the strength label as proof that the account is safe. Phishing, malware, reused recovery answers, and compromised email can bypass guessing entirely. The generator addresses creation, not the rest of account security.

Never reduce length merely to satisfy an arbitrary visual label. Follow the destination's maximum length and permitted characters, then prefer additional randomness. If a site rejects a symbol, regenerate with that class disabled rather than manually turning a strong value into a memorable pattern.

Checking an existing password

The checker is educational and operates locally, but entering a real current password into any web page can conflict with organizational policy. Prefer testing a structurally similar dummy value. A local estimate cannot tell whether a password appears in a breach corpus, whether another device recorded it, or whether the account has effective rate limiting.

When replacing a weak credential, generate a completely unrelated value, update the manager, revoke old sessions if the service supports it, and review recovery details. Do not rotate strong unique passwords on a calendar unless policy requires it or there is evidence of exposure; needless rotation can encourage weaker patterns.
