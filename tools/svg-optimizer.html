02 / EXPORT

Cleaning, embedding and exporting SVG files

Why SVG works well on the web

Scalable Vector Graphics (SVG) is an XML-based language that describes an image as shapes and paths rather than a grid of pixels, so a browser can render the same file cleanly at any size. The same markup can be placed inline in a page, referenced from an <img> element, used as a CSS background image, or drawn onto a canvas to produce a raster file. Each route has different trade-offs for styling, caching, accessibility and security.

SVG is not automatically smaller than a PNG. MDN notes that SVG can get complicated very quickly, so file sizes can grow and complex drawings can take significant processing time in the browser, and that raster formats are arguably better for complex images such as photos. Compare the file size and the visual result at the size where the image will actually appear.

What this tool keeps and what it removes

The optimizer parses your input as XML and rebuilds it from an allowlist. It keeps basic shapes, paths, groups, defs, use, symbol, linear and radial gradients with their stops, clip paths, masks, patterns, text (text, tspan, textPath) and the title and desc elements. On those elements it copies geometry, fill and stroke settings, opacity, transforms, gradient and pattern settings, font family, size and weight, and the role, aria-label and aria-hidden attributes. A style attribute is split into separate presentation attributes when a declaration sets a supported fill, stroke, opacity, colour, clipping, mask, stop or font property; other declarations are dropped. Coordinates and path data are not rounded or simplified; attribute values are only trimmed, with tabs and line breaks turned into spaces. The result is written out without the XML declaration, comments or formatting whitespace.

Everything else is removed, and an element that is not on the list is removed together with everything inside it. In practice that means:

  • <script> elements, event-handler attributes such as onclick, <foreignObject> (embedded HTML) and animation elements;
  • <style> blocks and class attributes, so artwork coloured through CSS classes loses those colours;
  • <image> elements, whether they point to another file or embed one, and any attribute whose value contains an http:, https:, data:, file: or javascript: URL;
  • filters, markers, <a> links and <switch> blocks, including any shapes inside them;
  • display and visibility settings, so anything hidden with them becomes visible;
  • references that leave the file: href must point to a local #id, and a url() value is kept only in the exact form url(#id);
  • <metadata> and other editor-specific elements or attributes from other namespaces;
  • empty groups and empty defs, gradient, clip-path, mask, pattern and symbol elements. A gradient with no stop elements of its own, one that borrows its stops from another gradient through href, counts as empty, so shapes that use it lose that gradient.

Files larger than 2 MB and files that contain a DOCTYPE or entity declaration are refused outright rather than cleaned. Remove the declaration before pasting, and if the file uses entities defined there, replace them with their values. The status line under the editor reports how many elements and attributes were removed; any non-zero count is a reason to compare the preview with your original artwork. If your source depends on one of the removed features, use a specialised workflow for that asset.

The metrics show the original and cleaned sizes in UTF-8 bytes and the change as a percentage. A tiny or already compact file can come out larger, for example when the SVG namespace has to be added; that is shown as a plus figure rather than as a saving.

Why scripts and outside references are stripped

An SVG file can be an active document. MDN's scripting guide explains that scripts inside an SVG run when the file is loaded as a document (opened directly, or embedded with <object>, <iframe> or <embed>) but never run when the same file is referenced by <img> or a CSS property such as background-image. This tool sanitizes before it builds the preview and before it offers a download, because a downloaded file may later be opened on its own. Do not assume that every online SVG minifier gives the same protection; check what it keeps.

Loading performance

Start with the smallest asset that still looks right: export with a sensible viewBox and delete layers you do not need in your editor, rather than hiding them, because content hidden with display or visibility becomes visible here. The delivery method matters as much as the bytes. MDN's guide to vector graphics in HTML notes that an SVG referenced from <img> can be cached by the browser for later pages, while inline SVG saves an HTTP request but cannot be cached that way and adds to the size of the HTML file. A CSS data URI also avoids a separate request, because the file is embedded in the stylesheet itself.

Judge the result by transferred bytes on the deployed site, not only by the uncompressed size; SVG is text and can be compressed for transfer. Drawing complexity has its own cost, since complex SVGs can take significant processing time in the browser however tightly the markup is written.

Give each image dimensions so the browser can reserve its space: MDN's <img> reference explains that width and height let the browser calculate the aspect ratio before the image loads, reducing layout shift. Write meaningful alt text for informative images and an empty alt="" for decorative ones. The cleaned output keeps <title>, <desc>, role, aria-label and aria-hidden when your source has them, but it adds none; the right choice depends on where you place the graphic.

React JSX output

React writes many SVG attributes in camelCase; its JSX guide gives strokeWidth in place of stroke-width. The JSX tab converts every hyphenated attribute that survives cleaning the same way (fill-rule becomes fillRule, stop-color becomes stopColor), leaves aria-* attributes unchanged, and wraps the markup in export default function Icon(props) with {...props} spread onto the root <svg>. Text content is written as quoted JSX expressions. The TypeScript switch adds import type * as React from 'react' and types the props as React.SVGProps<SVGSVGElement>.

The component is always named Icon, so rename it by meaning, such as SearchIcon or WarningIcon. Fill and stroke colours are kept exactly as in the source. For a monochrome icon that should follow the surrounding text colour, replace them with currentColor, which MDN describes as the value of the element's color property. Verify the component in your project's own React version and build pipeline before shipping it.

Not every SVG needs to become a component. JSX puts the path data into your JavaScript bundle, so a large illustration that never changes colour can be served as a separate file instead. In Next.js, files in the public folder are served from the site root, and the Next.js documentation notes that they are sent with Cache-Control: public, max-age=0 by default because they may change.

CSS data URI, inline SVG or an image file

The CSS tab percent-encodes the cleaned markup with encodeURIComponent, also encoding apostrophes so they cannot end the url('…') string, and writes three declarations: background-image: url('data:image/svg+xml;charset=utf-8,…'), background-repeat: no-repeat and background-size: contain. That suits a small decorative mark. The image travels inside the stylesheet rather than as its own file, and MDN's background-image reference notes that browsers give assistive technology no information about background images, so never make one the only carrier of important information.

Inline SVG, including the JSX output, lives in the document. MDN lists its advantages as saving an HTTP request and letting you style individual elements with CSS, including :focus styles and CSS animations. An <img> reference is simpler and cacheable, but its content cannot be manipulated with JavaScript, and CSS can style that content only from inside the SVG file. Pick based on what the graphic has to do: decoration in CSS, colour-aware interface icons as JSX, and large static artwork as a separate SVG file.

When to export PNG

Export PNG when the destination does not take SVG. Meta's sharing guide, for example, lists only image/jpeg, image/gif and image/png as values for og:image:type. The PNG tab draws the cleaned SVG onto a canvas at 1×, 2× or 4× its size, or at a custom width with the height following the aspect ratio, then encodes it with the canvas toBlob() method and downloads it. Transparent leaves the canvas clear; White and Black fill it with that colour first.

1× means the width and height written on the SVG, in pixels. If they are missing or use another unit such as % or mm, the viewBox size is used, and a file with neither is treated as 512 px wide. A 4× export has sixteen times the pixels of a 1× export, so file size and memory use climb quickly; the tool refuses any output wider or taller than 8192 px or larger than 32 million pixels. For large print work, use a dedicated graphics application and check its colour management.

The PNG can differ from the preview. The Checker, Dark and Light buttons only change the stage behind the preview; the PNG background is chosen separately. Text is drawn with fonts the browser has available, and because stylesheets are removed, a web font that the SVG loaded through CSS is not used. Open the downloaded PNG itself before relying on it.

A quick production checklist

  • Paste the markup, drop a file or browse for one, then compare the cleaned preview with the original artwork.
  • If the status line reports removals, check gradients, masks, text, filters, linked content and any colours that came from CSS classes.
  • Read the Change figure; a plus value means the cleaned file is larger than the source.
  • Choose JSX for styleable interface icons, a separate SVG file for large or widely reused static images, and a data URI for small decoration.
  • Rename the generated component and test it in your project's React version and build pipeline.
  • Export PNG at the dimensions the receiving product asks for, with the background it expects.
  • Give informative images alternative text and decorative ones an empty alt.

Frequently asked questions

Does this tool upload my SVG?

No. Parsing, cleaning, conversion, preview and PNG export all happen in your browser, and the page sends no request containing your SVG. The page itself loads Google Fonts and the Google AdSense script.

Why did part of my SVG disappear?

The cleaner drops every element and attribute that is not on its allowlist, and an unsupported element takes its contents with it. The usual causes are colours set through a <style> block, filters such as drop shadows, embedded images, content wrapped in <a> or <switch>, and gradients that borrow their stops from another gradient. When you must keep an advanced effect, use a specialist optimizer for that file.

Why is my SVG rejected?

The tool stops with a message when the XML is malformed, when the root element is not <svg>, when the file contains a DOCTYPE or entity declaration, or when it is larger than 2 MB. File uploads must have an .svg name or the image/svg+xml type.
