JSON formatting, validation and TypeScript types

JSON fundamentals

JavaScript Object Notation, better known as JSON, is a text format for representing structured data. It was derived from JavaScript but is language-independent, and it is defined by RFC 8259 and ECMA-404. A JSON document contains one value, and that value can be an object, an array, a string, a number, the literal true, the literal false, or null.

Objects use curly braces and contain name–value pairs. Every object name must be a double-quoted string, followed by a colon and its value. Commas separate members. Arrays use square brackets and contain an ordered list of values. JSON strings require double quotes; single quotes, template literals, comments, functions, undefined, NaN, and trailing commas are not part of valid JSON, even though JavaScript object literals can contain them.

Whitespace may appear between structural tokens and does not change meaning, so a multi-line document and its one-line minified equivalent hold the same data. Any Unicode text may appear inside a string, but quotation marks, backslashes and control characters must be escaped. A backslash begins an escape such as \n for a newline, \t for a tab, or \u followed by four hexadecimal digits. Numbers may include a fractional or exponent part, but leading zeros and non-finite values such as Infinity are prohibited.

Formatting and minifying

A formatter parses a JSON string into an in-memory value and serializes it again with predictable indentation. This tool parses your input with the browser's built-in JSON.parse shortly after you stop typing and shows the result in the Formatted JSON tab, always indented with two spaces; there is no setting for other widths or for tabs. Prettify, or Ctrl/Cmd + Enter in the input box, replaces your input with that two-space version.

Minification removes the optional whitespace so the same data occupies fewer bytes. Minify rewrites the input box as a single line, but the output panel, Copy and Download still use the two-space version, so copy minified JSON from the input box. Minified JSON is the same data, and formatting it again restores the layout.

Formatting cannot repair invalid input. If parsing fails, your input stays as typed, the output panel shows "Fix the JSON error to generate output.", and the status line shows the error message from the browser's JavaScript engine. Depending on the message, it gives a character position, a line and column, or no location at all. When the message contains a position, the tool adds the matching line and column in front of it.

A successful parse can still change details, because the output is rebuilt from JavaScript values rather than copied from your text:

  • Duplicate names: when an object repeats a name, only the last value is kept. RFC 8259 says software receiving duplicate names behaves unpredictably, so avoid them.
  • Large or very precise numbers: every number becomes a double-precision value. RFC 8259 treats integers up to 9,007,199,254,740,991 in magnitude as interoperable; beyond that, digits can change, so 12345678901234567890 is printed as 12345678901234567000. Values such as 1.0 and 1e2 are printed as 1 and 100.
  • Key order: keys that look like array indexes, such as "2" or "10", move to the front in ascending numeric order; other keys keep their original order.
  • Escapes: an escape such as é is printed as the character itself (é); quotation marks, backslashes and control characters stay escaped.

Debugging common parse errors

When the message gives a location, start there, then inspect the token just before it. With a trailing comma, for example, the error points at the closing bracket that follows the comma rather than at the comma itself.

  • Unexpected token or character: look for single-quoted strings, unquoted property names, comments, or a stray symbol copied from surrounding source code.
  • Expected comma or closing brace: check the previous property or array element. Adjacent values need a comma, while the final member must not have a trailing comma.
  • Unterminated string or bad control character: find a missing closing quote, an unescaped quote inside the value, or a raw line break inside a string. Windows paths also require escaped backslashes.
  • Unexpected end of input: the text stops before every brace, bracket or string is closed. Count them, and check whether the input was cut off.
  • Invalid number: remove a leading zero, a decimal point with no digit after it, hexadecimal notation, or a non-finite value such as NaN.

If the input starts with <, it is HTML, such as an error page, rather than JSON. JSON exchanged between systems that are not part of a closed ecosystem must be encoded as UTF-8, and a byte order mark must not be added to the start of JSON sent over a network. The browser parser used here rejects a leading byte order mark, and it rejects curly “smart” quotes used in place of straight double quotes.

From JSON to TypeScript interfaces

JSON carries values at runtime; TypeScript describes shapes during development. Turning a representative payload into interfaces lets an editor offer completions and lets the type checker flag misspelled property names before code ships. For an object, each key becomes a property. Strings, numbers, booleans and null values map to the types string, number, boolean and null, nested objects become named interfaces, and arrays become element-type arrays such as string[].

The TypeScript Interfaces tab walks the parsed value recursively. Interface names are built in PascalCase from the property path, such as Root, RootOwner and RootReleasesItem, and keys that are not valid identifiers, such as "my-key", are quoted. When every element of an array is an object, the elements are merged into one interface: a key missing from some elements is marked optional with ?, and a key whose values differ gets a union such as null | string. Arrays whose elements have mixed types get a union element type such as (number | string)[]. An empty array becomes unknown[] because it contains no evidence about its members, and a null sample stays null; widen it to a union such as string | null when the API allows both. A top-level array or primitive becomes export type Root.

Nested objects with the same shape are not merged. Sibling objects get separate interfaces, such as RootA and RootB, and an object repeated in each element of an array gets one interface per element, such as RootItemO and RootItemO2, joined in a union. Combine them by hand.

Generated interfaces are a starting point, not a replacement for an API contract. A sample cannot show fields it does not contain, optional keys are detected only inside arrays of objects, and TypeScript has a single number type for integers and fractions alike. JSON has no date type either, so ISO timestamps are typed as string. Compare several representative responses and refine the types deliberately.

TypeScript type annotations are erased when code is compiled and never change runtime behavior, so generated interfaces do not check incoming data. Validate untrusted network or user data at runtime before treating it as one of these types.

Rename generated names to terms your team recognizes. Consider readonly properties for data that should not be reassigned, and discriminated unions, whose members share a property with literal types, for variants.

A reliable workflow

Keep the raw payload somewhere else before you start. Prettify and Minify overwrite the input box, and the round trip described above can change duplicate names, large numbers and key order. Inspect the formatted copy, generate the initial types, then add runtime validation at the trust boundary. Do not rely on object key order for business logic: JSON objects are unordered, and parsers differ in whether they expose member order. Use arrays when order carries meaning.

Frequently asked questions

Why is valid JavaScript sometimes invalid JSON?

JavaScript object literals allow things JSON does not, including comments, single-quoted strings, trailing commas, unquoted property names and undefined. JSON keeps a smaller, language-independent grammar.

Can JSON contain comments?

Standard JSON cannot. Put explanatory metadata in ordinary properties, keep separate documentation, or use a format that supports comments, such as JSON5 or YAML. Stripping comments automatically is risky because comment-like text, such as the // in a URL, can appear inside strings.

Why did an empty array become unknown[]?

There are no elements from which to infer a type. TypeScript's unknown represents any value, but TypeScript does not allow anything to be done with an unknown value, which keeps the uncertainty explicit. Replace it with the real element type after checking documentation or additional responses.

Does generated TypeScript validate API responses?

No. Interfaces improve static checking in your source code but do not inspect runtime values. Pair them with runtime checks at every untrusted boundary.

What is the maximum JSON size?

The tool sets no limit of its own. Every pause in typing re-runs parsing, formatting, syntax highlighting and type generation on the whole document, so very large inputs respond more slowly.
